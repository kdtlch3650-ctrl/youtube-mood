# AI 설계 초안

## 1. 문서 목적

이 문서는 사용자가 입력한 자연어 문장을 분석해서 감정과 분위기를 추론하고, 그 결과를 음악 추천에 연결하기 위한 AI 모델의 방향을 정리한다.

이 프로젝트의 AI는 단순 분류기가 아니라 다음 역할을 함께 수행한다.

- 사용자의 현재 상태를 감정 태그로 정리한다.
- 음악 추천에 필요한 분위기 태그를 추론한다.
- YouTube 검색에 사용할 키워드로 변환할 수 있는 기준을 제공한다.

## 2. AI가 맡을 역할

AI는 사용자의 입력 문장을 보고 다음 정보를 반환한다.

- `emotions`: 사용자의 감정 상태
- `mood_tags`: 음악 분위기 태그
- `search_keywords`: YouTube 검색용 키워드

이 프로젝트에서는 감정과 분위기를 분리해서 다룬다.

- 감정은 "사용자가 지금 어떤 상태인가"를 나타낸다.
- 분위기는 "어떤 음악이 어울리는가"를 나타낸다.

이렇게 나누면 복합 감정을 더 자연스럽게 처리할 수 있다.

## 3. 입력과 출력

### 입력

- 사용자가 입력한 자연어 문장 1개

예시:

- `지쳤지만 너무 무거운 음악은 싫고, 조금 차분한 분위기가 좋다`
- `집중이 필요하지만 너무 딱딱하지 않은 음악을 듣고 싶다`
- `기분이 조금 가라앉았는데 따뜻한 음악이 듣고 싶다`

### 출력

AI는 아래 형식으로 결과를 반환한다.

```json
{
  "emotions": ["tired", "calm"],
  "mood_tags": ["soft", "quiet"],
  "search_keywords": [
    "calm soft music",
    "tired quiet playlist",
    "soft relaxing music"
  ]
}
```

## 4. 1차 태그 목록

### 감정 태그

다음 태그를 1차 버전의 대표 감정으로 사용한다.

- `calm` - 차분함
- `tired` - 지침
- `sad` - 슬픔
- `anxious` - 불안함
- `focused` - 집중함
- `stressed` - 스트레스
- `angry` - 화남
- `lonely` - 외로움
- `hopeful` - 기대감
- `happy` - 기쁨

### 분위기 태그

다음 태그를 1차 버전의 대표 분위기로 사용한다.

- `soft` - 부드러운
- `warm` - 따뜻한
- `light` - 가벼운
- `heavy` - 무거운
- `quiet` - 조용한
- `dreamy` - 몽환적인
- `uplifting` - 기분이 올라가는
- `minimal` - 미니멀한
- `late night` - 늦은 밤
- `acoustic` - 어쿠스틱한

## 5. 복합 감정 처리

이 프로젝트는 한 문장을 한 감정으로만 단순화하지 않는다.

예시:

- `tired + calm` - 지쳤지만 차분한 상태
- `anxious + soft` - 불안하지만 너무 무겁지 않은 음악이 필요한 상태
- `focused + quiet` - 집중이 필요하고 조용한 분위기가 맞는 상태
- `sad + warm` - 슬프지만 차갑지 않은 위로가 필요한 상태
- `angry + heavy` - 화가 나 있고 감정이 강한 상태

AI는 감정을 하나만 고르기보다, 필요하면 여러 개를 함께 반환해야 한다.

## 6. 검색어 생성 원칙

`search_keywords`는 AI가 직접 완성형 문장을 다 만들기보다, 감정 태그와 분위기 태그를 바탕으로 백엔드가 조합하는 편이 안정적이다.

이유:

- 검색어가 너무 들쭉날쭉해지지 않는다.
- YouTube 검색 결과가 더 일관된다.
- 디버깅이 쉽다.

예시 조합:

- `calm soft music`
- `tired but warm playlist`
- `focused quiet music`
- `angry heavy music`

## 7. 구현 방식

### 1차 구현

초기 버전에서는 너무 큰 모델보다, 다중 라벨 분류 구조가 적합하다.

추천 방식:

- 입력 문장 1개를 받는다.
- 감정 태그를 여러 개 예측한다.
- 분위기 태그를 여러 개 예측한다.
- 결과를 JSON으로 반환한다.

### 추천 출력 형태

`emotions`와 `mood_tags`는 배열로 반환한다.

- 감정은 최대 2~3개 정도
- 분위기는 최대 2~4개 정도

이 범위를 넘기면 결과가 너무 복잡해질 수 있다.

### 추론 후 처리

AI가 반환한 값은 바로 화면에 쓰기보다 백엔드에서 정리한 뒤 전달한다.

- 감정과 분위기 중 중복되는 값 제거
- 검색어 조합
- YouTube 추천 결과 생성

## 8. 학습 데이터 형식 초안

학습 데이터는 다음처럼 준비한다.

```json
{
  "text": "지쳤지만 너무 무거운 음악은 싫고 조금 차분한 분위기가 좋다",
  "emotions": ["tired", "calm"],
  "mood_tags": ["soft", "quiet"]
}
```

### 데이터 구성 기준

- 문장 1개당 감정 태그와 분위기 태그를 함께 넣는다.
- 복합 감정을 포함한 예시를 충분히 넣는다.
- 같은 의미라도 다른 표현으로 여러 번 넣는다.

예시 분류:

- `지침` / `피곤함` / `기운이 없음`
- `불안함` / `걱정됨` / `마음이 무거움`
- `화남` / `짜증남` / `답답함`

## 9. 백엔드 연결 방식

현재 백엔드의 `POST /api/analyze`는 목업 응답을 반환한다.

실제 모델이 준비되면 이 목업을 아래 구조로 교체한다.

1. 사용자가 문장을 입력한다.
2. 백엔드가 AI 모델에 문장을 전달한다.
3. AI가 `emotions`, `mood_tags`, `search_keywords`를 반환한다.
4. 백엔드가 YouTube 추천용 키워드를 정리한다.
5. 추천 곡과 플레이리스트를 함께 반환한다.

## 10. 구현 우선순위

1. 감정과 분위기 태그 목록을 고정한다.
2. 학습 데이터 형식을 정한다.
3. 추론 결과 JSON 형식을 고정한다.
4. 목업 응답을 실제 모델 결과로 교체한다.
5. 추천 검색어 생성 규칙을 안정화한다.

## 11. 확인해야 할 점

- 감정 태그를 어디까지 세분화할지
- 분위기 태그를 얼마나 유지할지
- 검색어를 AI가 직접 만들지, 백엔드가 조합할지
- 복합 감정 결과를 몇 개까지 보여줄지
