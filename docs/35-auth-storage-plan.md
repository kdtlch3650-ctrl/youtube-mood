# 인증과 저장소 구현 순서

이 문서는 Google 로그인과 검색 기록 저장을 AWS에 붙일 때의 최소 구현 순서를 정리한 초안이다.

## 현재 결정

- 로그인은 `Google + Cognito`로 처리한다.
- 검색 기록은 `OpenSearch`에 저장한다.
- 저장소는 나중에 교체하기 쉽도록 인터페이스를 분리한다.

## 현재 코드 상태

- 검색 기록은 아직 메모리 저장 방식이다.
- `SearchRecordRepository` 인터페이스를 추가해서 저장소를 교체할 수 있게 준비했다.
- `SearchRecord`에 `user_id`, `user_email` 필드를 예약해 두었다.

## 다음 구현 순서

1. Cognito 로그인 값 정리
2. 로그인 후 받을 사용자 식별자 정의
3. OpenSearch 인덱스 구조 확정
4. 저장소 구현을 OpenSearch 어댑터로 교체

## 주의할 점

- 로그인과 저장소를 한 번에 완성하기보다, 먼저 저장 구조를 분리하는 편이 안전하다.
- 검색 기록은 화면에서 조회와 필터가 필요하므로, 단순 파일 저장보다 OpenSearch가 더 맞다.
