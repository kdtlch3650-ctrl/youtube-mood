# 인증과 기록 저장 구조 정리

이 문서는 현재 프로젝트에서 로그인과 기록 저장을 어떻게 단순화했는지 정리한다.

## 현재 방향

- Cognito 로그인은 사용하지 않는다.
- 브라우저마다 자동 생성되는 세션 ID로 기록을 구분한다.
- 검색 기록은 OpenSearch에 저장한다.
- 기록 조회도 같은 세션 ID를 기준으로 가져온다.

## 왜 이렇게 바꿨는가

- Cognito는 HTTPS 설정과 배포 도메인 준비가 필요했다.
- 무료 환경에서는 이 구성이 생각보다 번거로웠다.
- 로그인보다 추천/기록 기능을 먼저 안정화하는 편이 더 중요했다.

## 현재 동작 방식

1. 브라우저가 처음 열리면 세션 ID를 하나 만든다.
2. 검색 요청과 기록 조회 요청에 그 세션 ID를 함께 보낸다.
3. 백엔드는 그 세션 ID를 기준으로 기록을 저장하고 조회한다.
4. 로그인 화면 없이 바로 추천 기능을 사용할 수 있다.

## 나중에 다시 고려할 수 있는 것

- 실제 Google 로그인
- 사용자 계정별 기록 분리
- 배포 환경에서의 정식 인증 구조
