# EKS Ingress Controller 초안

이 문서는 EKS에서 `Ingress`를 실제로 동작시키기 위해 필요한 컨트롤러 방향을 정리한 초안이다.

## 추천 방향

현재 프로젝트에는 **AWS Load Balancer Controller**를 쓰는 방향이 가장 맞다.

이유:

- EKS와 자연스럽게 연결된다
- `Ingress` 매니페스트를 유지하기 쉽다
- 하나의 외부 주소로 `/api`와 `/`를 나누는 구조와 잘 맞는다
- 나중에 도메인 연결과 SSL 적용을 붙이기 편하다

## 역할

- Kubernetes `Ingress`를 읽는다
- AWS 쪽 로드밸런서를 만든다
- 외부 요청을 백엔드와 프론트 서비스로 나눈다

## 설치 전에 확인할 것

- EKS 클러스터가 먼저 생성되어 있는가
- `kubectl`로 클러스터 접속이 되는가
- ECR 이미지가 준비되어 있는가
- `k8s/ingress/ingress.yaml`이 현재 서비스 이름과 맞는가

## 지금 프로젝트에서의 흐름

1. ECR에 이미지를 올린다
2. EKS 매니페스트를 적용한다
3. AWS Load Balancer Controller를 설치한다
4. Ingress가 외부 주소를 받는지 확인한다
5. `/api`와 `/` 경로가 각각 올바르게 연결되는지 확인한다

## 주의할 점

- 컨트롤러 설치 전에 Ingress만 적용하면 외부 주소가 바로 안 붙을 수 있다
- AWS 리소스가 생기므로 비용이 발생할 수 있다
- 로컬 `kind`에는 이 컨트롤러가 필요하지 않다
