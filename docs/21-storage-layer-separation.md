# 저장 계층 분리 초안

이 문서는 검색 기록을 만들기와 저장하기를 분리한 이유를 정리한다.

## 지금 구조

- `build_search_record(...)`
  - 분석 결과와 추천 결과를 받아서 기록 객체를 만든다
- `save_search_record(...)`
  - 만들어진 기록 객체를 저장한다
- `list_search_records()`
  - 저장된 기록을 조회한다

## 왜 나눴는가

- OpenSearch로 저장소를 바꿀 때 저장 함수만 교체하기 쉽다
- 기록 객체 구조는 그대로 유지할 수 있다
- API는 크게 바꾸지 않아도 된다

## 현재 저장 방식

- 메모리 저장
- 서버를 재시작하면 기록은 사라진다

## 다음 단계

1. 저장 함수를 OpenSearch 저장 함수로 교체
2. 조회 함수를 OpenSearch 검색 함수로 교체
3. API는 그대로 유지
