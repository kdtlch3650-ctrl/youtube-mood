# EKS Ingress 준비 초안

이 문서는 EKS에서 외부 요청을 애플리케이션으로 연결하는 방법을 정리한 초안이다.

현재 로컬과 EKS 매니페스트에는 `Ingress` 리소스가 들어 있다.  
하지만 EKS에서는 `Ingress`만 적용한다고 외부 접속이 자동으로 열리지는 않는다.  
Ingress를 실제로 처리해 줄 컨트롤러가 필요하다.

## 왜 필요한가

- 백엔드와 프론트 서비스는 내부 서비스로 유지하고 싶다
- 외부에서는 하나의 주소로 들어오게 하고 싶다
- `/api`는 백엔드로, `/`는 프론트로 보내고 싶다

## 현재 구조

- `k8s/backend/service.yaml`은 백엔드 내부 서비스
- `k8s/frontend/service.yaml`은 프론트 내부 서비스
- `k8s/ingress/ingress.yaml`이 경로 분기를 담당

## 선택지

### 1. Ingress Controller 사용

- 장점
  - 지금 만든 `Ingress` 매니페스트를 그대로 살릴 수 있다
  - 경로 기반 분기가 가능하다
  - 나중에 도메인 연결하기 쉽다
- 단점
  - 컨트롤러 설치가 추가로 필요하다
  - EKS 설정이 조금 더 늘어난다

### 2. Service를 직접 외부 노출

- 장점
  - 구조가 단순하다
- 단점
  - 백엔드와 프론트를 따로 노출해야 할 수 있다
  - 지금 `Ingress` 기반 설계와는 맞지 않는다

## 추천 방향

지금 프로젝트에는 Ingress Controller 방식이 더 맞다.

이유:

- 경로 분기를 한 곳에서 관리할 수 있다
- 검색 화면과 API 경로를 한 주소 체계로 묶기 쉽다
- 포트폴리오 설명에도 구조가 깔끔하다

## 다음에 할 일

- 어떤 Ingress Controller를 쓸지 정한다
- 설치 후 `k8s/ingress/ingress.yaml`을 EKS에 맞게 조정한다
- 외부 주소가 붙는지 확인한다

## 확인 기준

- `kubectl apply -f k8s/ingress/ingress.yaml`가 에러 없이 실행된다
- 외부 주소가 생성된다
- `/api`와 `/`가 각각 올바른 서비스로 연결된다
