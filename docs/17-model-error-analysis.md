# 모델 실패 케이스 분석

## 1. 문서 목적

이 문서는 감정 예측 모델과 추천 로직에서 기대와 다르게 동작한 사례를 모아두는 곳이다.

새로운 실패 케이스가 발견될 때마다 이 문서에 추가하고, 이후 라벨 매핑, threshold, 학습 데이터, 검색어 생성 로직을 조정하는 기준으로 사용한다.

## 2. 기록 방식

아래 항목을 기준으로 사례를 기록한다.

- 입력 문장
- 기대 감정
- 실제 감정
- 기대 분위기 태그
- 실제 분위기 태그
- 기대 장르
- 실제 검색어
- 문제 원인 추정
- 개선 아이디어

## 3. 실패 케이스 예시

### 3.1 감정은 불안하지만 너무 무거운 음악은 싫은 경우

입력 문장:

```text
불안하지만 너무 무거운 음악은 싫어
```

기대 감정:

```text
anxiety
```

기대 분위기 태그:

```text
soft, light, quiet
```

실제 결과:

```text
anxiety 계열로 인식되지만 회피 표현에 따라 분위기 태그가 보정된다.
```

문제 원인 추정:

- 감정 자체는 맞더라도 회피 표현이 없으면 `heavy`나 `late night`으로 치우칠 수 있다.

개선 아이디어:

- 회피 표현 목록 확장
- `heavy`와 `late night` 보정 조건 강화

### 3.2 지쳤지만 신나는 음악을 원하는 경우

입력 문장:

```text
오늘은 특히 너무 지쳐 신나는 댄스음악 추천해줘
```

기대 감정:

```text
tiredness + positive
```

기대 분위기 태그:

```text
uplifting, light, warm
```

실제 결과:

```text
tiredness와 positive가 함께 인식된다.
```

문제 원인 추정:

- 지침 상태와 활기 선호가 동시에 들어간 복합 문장이라 단일 감정으로는 설명이 어렵다.

개선 아이디어:

- 복합 감정 조합이 자주 나오는 패턴을 별도 기록
- 추천 검색어 생성 시 `uplifting` 우선순위 유지

### 3.3 장르가 아닌 단어를 장르로 잘못 잡을 가능성이 있는 경우

입력 문장:

```text
요즘 자꾸 함정에 빠지는 것 같아서 답답한데 음악 추천해줘
```

기대 감정:

```text
irritation or stress
```

기대 장르:

```text
없음
```

실제 결과:

```text
장르 없음
```

문제 원인 추정:

- `trap` 같은 단어와 문맥이 비슷할 수 있어 오탐 가능성이 있다.

개선 아이디어:

- 부정 추천 문맥 추가
- 애매한 장르에 대한 문맥 규칙 유지

## 5. 사용 방식

새로운 문장을 테스트했을 때 아래 중 하나라도 어색하면 이 문서에 기록한다.

- 감정이 틀린 경우
- 분위기 태그가 과하게 어두워지거나 밝아지는 경우
- 장르가 잘못 잡히는 경우
- 검색 옵션에 따라 결과가 너무 크게 흔들리는 경우
- 실제 추천 결과가 입력 의도와 거리가 먼 경우
